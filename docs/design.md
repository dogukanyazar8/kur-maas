# Kur Maaş

Confirmed policy: TCMB USD ForexBuying. January/April/July/October use the previous three calendar months' last published rates. For January, use October–December of the previous year.

Given constant monthly USD salary S and protected current salary rate B, average A = (r1+r2+r3)/3. Effective rate E = max(A,B). Difference D = max(A-B,0). Base salary S*E. Quarterly extra 3*S*D. Total = base + extra. Example S=1000, B=43, rates 44/45/46 yields base 45000, extra 6000, total 51000. A decline keeps both the base salary rate and payment protected. Ordinary months use the user-entered current protected rate, established at the last quarterly payment; the app explicitly explains this input. No automatic persisted history across sessions, payroll deductions, or intra-quarter salary changes.

Architecture: Next.js App Router, React, TypeScript. Pure decimal calculation and strict locale parsing on client. No salary persistence or transmission. A read-only API fetches only official TCMB rates from a fixed HTTPS host; bounded fetching, response-size limits, timeouts, strict XML validation, allowlisted UTF-8/ISO-8859-9 decoding, and bounded cache. Payment years start at 2006 to avoid old TL denomination data. Historical missing-publication days and upstream failures are separate states.

UI: Turkish and English language options separate from number format (TR/US/DE/FR). Accessible responsive light interface with deep teal result card, financial breakdown, monthly source dates and links, protected-rate explanation, and explicit manual scenario mode. Future or incomplete official periods cannot produce definitive results. Manual inputs and example values always carry a scenario label. Inputs invalidate previous results immediately. No external fonts, trackers, or salary storage.

Precision: decimal strings throughout; never parse localized text with parseFloat. Published/scenario rates accept four decimal places and salary two. Protected salary rates accept up to 50 fractional places; arithmetic precision is 100 significant digits. The next-month action carries the precise protected rate without re-entering the four-place display. Full precision used in intermediate calculations. Base and extra each round to kuruş with ROUND_HALF_UP; visible total is their sum. This rounding convention is disclosed in the interface and README.

Runtime: latest verified Node 24 LTS patch 24.20.0, portable workspace copy for verification because global Node is 24.18.0. Exact stable dependency versions and lockfile. Local startup binds to loopback. Railway uses a separate start command bound to 0.0.0.0 and reads PORT; railway.json declares the build, start and page health check. The initial GitHub publication was requested on September 9, 2026; live Railway verification is separate from local checks.

Validation: unit tests for policy, rounding, invalid inputs, locale rules, year rollover, and UTC-independent periods; adapter tests with realistic XML and fault cases; browser tests for the 51000 example, protection, regular salary, locale/language changes, stale state, network failure, accessibility, mobile width, Chromium/Firefox/WebKit; live TCMB smoke separately from deterministic fixtures; lint/typecheck/production build/dependency audit.

Scenario update: selecting Scenario fetches the available reference months through `/api/scenario-rates`. One Istanbul date snapshot determines availability. Completed months use month-end publications, the current reference month uses its latest publication up to today with a provisional label, and future months stay empty. Current-month cache uses a date key and a 60-second TTL; completed-month cache remains shared with official requests. Partial failures preserve other months. Field edits are protected against late autofill, changing the period aborts/clears old drafts, and number-format changes also govern pending responses. Unedited published values retain their source links; edited values carry manual provenance. The example remains deterministic and offline.

Control update: one Radix Select component styles language, number format, and payment month menus. Consistent trigger/option/focus states, keyboard navigation and focus return, portal placement and viewport collision handling. The k-and-dot logo uses a crisp inline vector; textboxes use one outer hover/focus treatment. Full-page accessibility checks run with menus closed; the active listbox is checked separately while open, with explicit keyboard/focus-trap checks.
